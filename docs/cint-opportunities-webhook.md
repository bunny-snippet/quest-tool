# Cint Feed Opportunities webhook

Quest now has a local/production-compatible receiver at:

`POST /api/cint/webhook/surveys`

The receiver accepts Cint's single-survey object and batched array payloads. It
verifies `X-Lucid-Signature` with ECDSA-SHA256, rejects stale timestamps,
deduplicates retries, and persists delivery audit counters.

## Subscription facts

- Cint permits one Opportunities subscription per Supplier Code.
- Creating a subscription replaces the existing subscription.
- `public_key` and `key_id` are returned by Cint; they are not POST fields.
- The current request field names are `payload_max_size_mb` and
  `payload_max_survey_count`.
- `include_quotas: true` includes quotas and qualifications in callbacks.

The future Quest subscription body is generated by
`surveys.cint_webhooks.subscription_payload(callback)`. Its filters accept:

- `eng_in`, `eng_us`, `eng_ca`, `fra_fr`, `hin_in`: RPI 1 through 4
- `eng_gb`: RPI 1 through 2
- `study_type`: `adhoc`

## Client API configuration (recommended)

Open **Client APIs**, edit the Cint integration, and enable **Feed
Opportunities webhook**. Save the values returned by the current Cint
subscription:

- Callback URL: `https://api.exchange-ip.com/api/cint/webhook/surveys`
- Webhook public key: base64 DER ECDSA public key
- Webhook key ID: subscription key ID
- Batch interval: 5 seconds (fixed by the application)
- Maximum surveys: 1,000 (fixed by the application)

The public key verifies callback signatures; it is not the Cint Supply API key.
The integration configuration takes precedence over environment fallbacks, so
key rotation does not require a code change.

## Environment fallback

```env
CINT_OPPORTUNITIES_WEBHOOK_ENABLED=true
CINT_OPPORTUNITIES_SUPPLIER_CODE=6528
CINT_OPPORTUNITIES_PUBLIC_KEY=<base64 DER key returned by Cint>
CINT_OPPORTUNITIES_KEY_ID=<key ID returned by Cint>
CINT_OPPORTUNITIES_SIGNATURE_TOLERANCE_SECONDS=300
CINT_OPPORTUNITIES_MAX_PAYLOAD_BYTES=10485760
CINT_OPPORTUNITIES_MAX_SURVEY_COUNT=1000
CINT_OPPORTUNITIES_PROCESS_SYNCHRONOUS=false
CINT_OPPORTUNITIES_QUEUE_REDIRECTS=true
```

`CINT_OPPORTUNITIES_LOCAL_TEST_TOKEN` enables unsigned requests only when
`DJANGO_DEBUG=true`, the caller is loopback, and the header value matches.

## Local replay

Start Django locally and send the committed fixture:

```powershell
$token = ((Get-Content .env | Where-Object {
  $_ -like "CINT_OPPORTUNITIES_LOCAL_TEST_TOKEN=*"
}) -split "=", 2)[1]
$headers = @{
  "Content-Type" = "application/json"
  "X-Cint-Local-Test-Token" = $token
}
$body = Get-Content -Raw docs/examples/cint-opportunities-webhook.json
Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/api/cint/webhook/surveys `
  -Headers $headers `
  -Body $body
```

This local bypass is impossible when `DEBUG=false` or when the request is not
from loopback. Production callbacks must always contain a valid
`X-Lucid-Signature` header.

## Update behavior

- `new`, `updated`, and `reactivated` eligible opportunities are upserted.
- `deactivated` or `is_live: false` closes existing inventory.
- Locale, RPI, and `adhoc` rules are rechecked before persistence.
- Webhook quotas and qualifications replace the corresponding local snapshot.
- Verified duplicate deliveries do not create or update inventory twice.
- Deliveries for one Cint integration are processed serially and an older
  retried delivery cannot overwrite a newer inventory snapshot.
- Production asynchronous processing queues supplier-link redirect provisioning
  for newly received inventory.

## Universal respondent result

Cint supplier links continue to return the internal MID using `rid=[%MID%]`.
The callback resolver attaches that value to the matching attempt, records the
final status, redacts the upstream `hash`, and immediately redirects the browser
to a clean platform URL:

`/survey?status=<1-4>&pid=<platform-pid>`

The attempt's internal RID and panelist UID are never rewritten.
